# Repository Onboarding Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the unconfigured dashboard with repository selection and a durable, animated, truthful first import of up to 100 PRs.

**Architecture:** Keep Next.js, PostgreSQL/Drizzle, and Inngest. Separate GitHub repository availability from repository tracking, persist an import run and its fixed PR batch, and let authenticated UI consumers observe that run. Reuse PR hydration and metrics without introducing code checkout or paid analysis.

**Tech Stack:** Existing Next.js 16.3.4, React 19.2.8, TypeScript, Drizzle/PostgreSQL, Octokit, Inngest, Vitest, and plain CSS; package versions remain as installed.

**Spec:** `docs/superpowers/specs/2026-09-08-repository-onboarding-design.md` (approved in conversation on 2026-09-08).

```ts
import type { ImportItem, ImportState } from './types';
export const isActiveImport = (state: ImportState) =>
  state === 'queued' || state === 'discovering' || state === 'importing';
export function summarizeImport(items: ImportItem[]) {
  const completed = items.filter(i => i.state === 'complete').length;
  const failed = items.filter(i => i.state === 'failed').length;
  const total = items.length;
  const state: ImportState = completed + failed < total ? 'importing'
    : failed === 0 ? 'complete' : completed === 0 ? 'failed' : 'partial';
  return { state, total, completed, failed };
}
```

- [ ] **5. Implement lifecycle queries with repository advisory locks.** Reuse the lock expression used by `persistPr`; acquire the repository lock before the run row lock consistently. Each mutation executes inside one transaction. `requestRepositoryImport` verifies active non-demo repository and installation, returns an existing active run, and makes selection plus run creation atomic. `start` returns the latest run even if terminal; `refresh` explicitly starts a new latest-100 batch for an already tracked repository; `retry` validates that the previous run belongs to the repository, is the latest failed/partial run (or already has a retry), and copies successful items while resetting every other item to pending. A failure before discovery keeps total null and permits discovery on retry.

`beginImport` only transitions queued to discovering/importing, according to whether total is null. `saveImportBatch` inserts distinct positive PR numbers, max 100, sets total once, and cannot overwrite discovery after replay. `recordImportItem` only changes a pending item on an active run and derives counts from rows, never increments counters blindly. export async function GET(_request: Request, context: {
```ts
  params: Promise<{ repoId: string; runId: string }>;
}) {
  if (!(await hasCurrentSession())) return Response.json({ error: 'Sign in again.' }, { status: 401 });
  const { repoId, runId } = await context.params;
  await requireRepository(repoId);
  const run = await getImport(runId);
  if (!run || run.snapshot.repositoryId !== repoId)
```
